# Git Commit 消息生成器

请根据 git 暂存区的变更生成可靠的 commit 消息，同时完成最必要的质量检查。

**⚠️ 全局警告：严禁在 commit 消息的任何字段内添加 AI 生成标识或署名**

## 核心流程

### 1. 前置检查
- 运行 `git status`，确认不在 merge/rebase/cherry-pick 等特殊状态
- 暂存区为空时立即提示用户；存在关键未暂存改动时建议一起提交或说明原因
- 粗略浏览 `git diff --cached --name-only`，如发现疑似产物（.env、node_modules、日志等），在输出中引用附加参考提醒用户处理
- 初次提交（无历史记录）时直接建议 `chore: initial commit` 或 `feat: 项目初始化`

### 2. 变更分析
- 运行 `git diff --staged --stat` 获取文件数与增删行概况
- 查看 `git diff --staged`，识别模块、文件类型
- 检查是否存在需要拆分的混合改动（≥3 个无关模块、文档与代码混杂等）
  - 若检测到需拆分，必须在输出中提醒用户并给出拆分建议
- 判断是否存在潜在破坏性变更（参考附加规则）并标记影响范围

### 3. Review 提示
**基础检查**（每次都做）：
- 敏感信息：是否泄露密钥、token、密码等
- 鉴权/权限：登录、权限验证相关逻辑是否有漏洞
- 代码质量：明显的命名问题、缺失的错误处理、过度复杂的逻辑
- 测试覆盖：关键流程是否有对应测试，缺失时提醒补充

**触发式深度检查**（根据变更内容）：
- 若涉及数据库结构、migration：说明潜在的向后兼容性影响
- 若涉及批量查询、循环操作：提示性能风险
- 若涉及配置格式变更：说明升级注意事项
- 若发现敏感代码（凭证、密钥）：必须明确警告并询问用户是否继续

### 4. Commit 消息生成
- 依据"Type 选择参考表"挑选最合适的 type
- 若存在 Breaking Change，使用 `type!` 并在 footer 加入 `BREAKING CHANGE: ...`
- **subject**：使用中文，≤50 字，描述核心影响
- **scope**：仅在能准确指明模块且不冗长时使用
- **body**：说明动机、实现方式、潜在风险或后续工作；多块内容使用空行分隔
- **footer**：列出关联 issue 或额外说明（如拆分建议、升级注意事项）
- **再次确认：严禁添加任何 AI 生成标识或署名**

### 5. 输出模板
以块状文本呈现，便于用户快速确认：

```
变更统计：<文件数> 个文件，+<新增行> -<删除行>
变更摘要：<一句话描述关键修改>
受影响模块：<文件/模块列表>
风险评估：<高|中|低，含理由>
Review 提醒：<安全/代码质量/测试/性能等发现，如无写"无">
.gitignore 检查：<问题文件或"无">

Commit 提议：
<type>(<scope>): <subject>

<body，如无可省略>

<footer，如无可省略>

确认动作：使用 / 编辑 / 取消？
```

**不要自动执行 git commit**，先展示生成的消息供用户确认。

## 附加参考

### Type 选择参考表
| 场景 | 建议 type |
| --- | --- |
| 破坏性功能调整或修复 | `feat!` / `fix!` |
| 新增特性、接口 | `feat` |
| Bug / 安全漏洞修复 | `fix` |
| 性能相关优化 | `perf` |
| 代码重构（无行为变化） | `refactor` |
| 测试代码 | `test` |
| 构建与依赖 | `build` / `chore` |
| CI 配置 | `ci` |
| 文档 | `docs` |
| 格式化、Lint | `style` |

优先级顺序：Breaking Change > feat/fix > perf > refactor > test/build/ci > docs/style

### 破坏性变更识别标准
- **API 变更**：接口签名修改、返回值变更、端点删除
- **数据库变更**：表结构修改、字段删除、类型变更
- **配置变更**：配置文件格式修改、必需配置项变更
- **依赖变更**：重大版本升级导致兼容性问题

### .gitignore 详细规则
**常见应该忽略的文件/目录**：
- 系统文件：`.DS_Store`, `Thumbs.db`, `Desktop.ini`
- IDE 文件：`.idea/`, `.vscode/`, `*.iml`, `*.swp`
- 日志文件：`*.log`, `logs/`
- 临时文件：`tmp/`, `temp/`, `*.tmp`
- 构建输出：`build/`, `dist/`, `target/`, `node_modules/`, `__pycache__/`
- 环境配置：`.env`, `.env.local`, `.env.*.local`
- 证书密钥：`*.jks`, `*.p12`, `*.pem`, `*.key`
- 数据库文件：`*.db`, `*.sqlite`, `*.sqlite3`

**处理建议**：
```bash
# 从暂存区移除
git reset HEAD <文件路径>

# 添加到 .gitignore
echo "<文件或目录>" >> .gitignore

# 删除已提交的文件
git rm --cached <文件路径>
```

### 深度检查触发信号（参考）
当在 diff 中检测到以下关键词/模式时，在"Review 提醒"中追加对应的深度检查内容：

- **数据库**（检测到 `ALTER TABLE`, `migration/`, `schema.rb`, `*.sql`）：
  - 说明向后兼容性影响，提示是否需要数据迁移计划

- **性能**（检测到 `SELECT *`, `for`循环 + 数据库调用, 大文件操作）：
  - 提示潜在性能风险，建议进行性能测试

- **配置**（检测到 `*.yml`, `*.json` 配置文件, `config/` 目录）：
  - 说明配置变更的升级影响，提醒更新文档

- **敏感**（检测到 `.env`, `password`, `secret`, `token`, `key`, `credential`）：
  - 明确警告存在敏感信息，询问用户是否确认提交
