# Git Commit 消息生成器

请根据 git 暂存区的变更生成可靠的 commit 消息，同时完成最必要的质量检查。

## 核心流程

### 1. 前置检查
- 运行 `git status`，确认不在 merge/rebase/cherry-pick 等特殊状态
  - 若处于特殊状态，提示用户先完成或中止当前操作，然后停止流程
- 暂存区为空时立即提示用户；存在关键未暂存改动时建议一起提交或说明原因
- 检查是否有 stash，若有则提醒用户是否需要先处理
- 粗略浏览 `git diff --staged --name-only`，如发现疑似产物（构建输出、依赖目录、环境配置、日志等），提醒用户处理
- 初次提交（无历史记录）时直接建议 `chore: initial commit` 或 `feat: 项目初始化`，跳过历史风格参考

### 2. 变更分析
- 运行 `git diff --staged --stat` 获取文件数与增删行概况
- 查看 `git diff --staged`，识别模块、文件类型
- 检查是否存在需要拆分的混合改动（≥3 个无关模块、文档与代码混杂等）
  - 若检测到需拆分，必须在输出中提醒用户并给出拆分建议
- 判断是否存在潜在破坏性变更（参考附加规则）并标记影响范围

### 3. Review 提示
**基础检查**（每次都做）：
- 敏感信息：是否泄露密钥、token、密码、硬编码凭证等
- 鉴权/权限：登录、权限验证相关逻辑是否有漏洞
- 代码质量：明显的命名问题、缺失的错误处理、过度复杂的逻辑
- 测试覆盖：关键流程是否有对应测试，缺失时提醒补充

**触发式深度检查**（根据项目类型和变更内容自动识别）：
- 若涉及数据持久化层变更（数据库 schema、ORM 实体、序列化结构等）：说明向后兼容性影响
- 若涉及批量/并发操作（大集合处理、并行任务、循环内 I/O 等）：提示性能风险
- 若涉及构建或项目配置变更：说明升级注意事项和依赖影响
- 若涉及破坏性变更（参考"破坏性变更识别标准"）：明确标记并提示影响范围

### 4. Commit 消息生成
- 运行 `git log --oneline -10` 参考项目已有的 commit 风格（语言、格式、scope 使用习惯）
- 依据"Type 选择参考表"挑选最合适的 type
- 若存在 Breaking Change，使用 `type!` 并在 footer 加入 `BREAKING CHANGE: ...`
- **subject**：≤50 字，描述核心影响，语言风格与项目历史保持一致
- **scope**：仅在能准确指明模块且不冗长时使用
- **body**：说明动机、实现方式、潜在风险或后续工作；多块内容使用空行分隔
- **footer**：列出关联 issue 或额外说明（如拆分建议、升级注意事项）

### 5. 输出模板
```
变更统计：N 个文件，+X -Y
变更摘要：一句话描述
受影响模块：模块列表
风险评估：高|中|低（理由）
Review 提醒：发现的问题，无则写"无"
.gitignore 检查：问题文件，无则写"无"

Commit 提议：
type(scope): subject

[body]

[footer]
```

> scope、body、footer 均为可选，无内容时省略

**风险评估标准**：
- **高**：涉及破坏性变更、安全相关、数据迁移、核心流程修改
- **中**：涉及多模块、配置变更、公开 API 调整
- **低**：单文件修改、文档更新、样式调整、测试补充

**确认动作**（展示后等待用户选择）：
- `使用`：执行 `git commit` 提交
- `编辑`：用户修改消息后再提交
- `取消`：放弃本次提交

## 附加参考

### Type 选择参考表
| 场景 | 建议 type |
| --- | --- |
| 破坏性功能调整或修复 | `feat!` / `fix!` |
| 新增特性、接口 | `feat` |
| Bug / 安全漏洞修复 | `fix` |
| 性能相关优化 | `perf` |
| 代码重构（无行为变化） | `refactor` |
| 测试代码 | `test` |
| 构建与依赖 | `build` / `chore` |
| CI 配置 | `ci` |
| 文档 | `docs` |
| 格式化、Lint | `style` |

优先级顺序：Breaking Change > feat/fix > perf > refactor > test/build/ci > docs/style

### 破坏性变更识别标准
- **API/接口变更**：公开接口签名修改、返回值变更、端点删除
- **数据层变更**：数据结构修改、字段删除、类型变更
- **配置变更**：配置文件格式修改、必需配置项变更
- **依赖变更**：重大版本升级导致兼容性问题

### .gitignore 检查
根据项目类型和技术栈，自动识别以下类别的文件是否应被忽略：
- 系统文件、IDE/编辑器配置
- 日志、临时文件
- 构建输出、依赖目录
- 环境配置、证书密钥、本地数据文件

发现问题时，提示用户使用 `git reset HEAD`、`git rm --cached` 或添加到 `.gitignore`。
