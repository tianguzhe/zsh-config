# 开发指南

正确性 > 可读性 > 性能。重构保持行为不变。代码风格由项目 linter/formatter 约束，不在此处重复。

## 正确性底线

- `catch` 必须记录、重抛或转显式返回值，禁止吞错
- 轮询/重试/爬取必须有显式最大次数变量
- 资源关闭覆盖所有退出路径（含异常）
- 函数签名应暗示副作用；禁止隐式写入可变全局状态
- 前提条件写成断言，而非注释
- 涉及钱/权限/用户数据/并发/加密时，主动提示用户审阅

## 协作约定

- 关键业务逻辑必须有测试覆盖；无法描述用例时先澄清需求
- 重构 legacy 代码前先补测试
- 注释必须英文；仅写 why（意图、约束、陷阱）
- 同一问题尝试 3 次未解决，停止试错，汇报现状与假设，等待指示
- 库/框架/API 不确定时，优先用 context7 或 exa 获取最新文档，禁止凭记忆编造或沿用废弃 API
