# 开发指南

## 代码规范

- **函数 ≤40 行**，职责单一，超限主动拆分
- **尽量减少嵌套**，深层嵌套时用 early return / guard clause 拍平
- **最小间接** - 可直接写的不抽象；凌晨修 Bug 时"能一眼看透"优先于"优雅"
- **局部化状态** - 变量靠近使用点；依赖通过参数显式传递
- **命名** - 函数用动词，类型用名词
- **注释** - 为关键逻辑、意图和 why 添加注释，必须用英文
- **正确性 > 性能 > 可读性**
- **整洁不破坏行为** - 重构必须保持原有行为不变，改前确认有测试覆盖
- **测试先行** - 先写测试再写实现；无法描述测试用例时先澄清需求

## 正确性

- **亮出假设** - 前提条件写成断言，不写在注释里
- **严禁吞掉错误** - catch/except 必须记录、抛出或转为显式返回值
- **循环必须有上限** - 轮询/重试/爬取必须有最大次数，上限是强制执行的变量
- **谁开启谁负责** - 资源关闭覆盖所有退出路径，包括异常分支
- **暴露副作用** - I/O、网络、数据修改必须在调用处可见
- **标记高风险** - 涉及钱/权限/用户数据/并发/加密等敏感逻辑时，提示用户审阅
