# Android dp 适配方案参考

## 原理

Android 的 dp（density-independent pixel）按设备屏幕密度换算成 px，但**不同设备的屏幕宽度（以 dp 计）差异很大**：小手机 320dp，主流 360-411dp，大屏 480+dp，平板 600+dp。

结果：设计稿按 375dp 画的一个 "20dp 间距"，在 320dp 屏幕上显得挤、在 600dp 平板上显得空。

### sw（smallestWidth）限定符方案

Android 支持 `values-sw<N>dp/` 资源目录——系统会根据设备"最短边的 dp 宽度"自动选择最接近的匹配。

通过为每个常见 sw 桶生成一份 `dimens.xml`，把设计稿上的 `20dp` 按比例换算成该屏宽下的值：

```
换算公式：target_value = design_value * (target_sw / base_sw)
例如 base=375，design=20dp，target=600 → 20 * 600/375 = 32dp
```

运行时布局里写 `@dimen/dp_20`，系统根据当前 sw 取对应桶里的值，即可实现"设计稿等比放大/缩小"。

## 常见 sw 桶

| sw | 典型设备 |
|----|---------|
| 320 | 小屏老设备 |
| 360 | Pixel 默认、多数主流安卓 |
| 375 | iPhone X 系（常用设计基准） |
| 392 / 411 | 华为、部分旗舰 |
| 420 / 480 | 大屏手机 |
| 600 | 7" 平板 |
| 720 / 800 | 10" 平板 |

## 命名约定（本 skill 使用）

- 正整数：`dp_16`、`dp_100`
- 正小数：`dp_0_5`、`dp_1_5`（下划线代替小数点）
- 负数：`dp__16`（双下划线前缀）
- 负小数：`dp__0_5`

原因：XML 属性名不允许 `-` 与 `.`，统一规则让 Kotlin/Java 侧 `R.dimen.dp_0_5` 能直接引用。

## 集成建议

1. 把生成目录指到 `app/src/main/res/`（或 `--output` 指定），会创建多个 `values-sw<N>dp/` 子目录。
2. 不要把 `values/dimens.xml`（默认兜底）删掉——为没有命中任何 sw 桶的设备兜底。通常用 base_sw 对应的那份当默认。
3. 设计稿尺寸直接 1:1 写成 dp 值，UI 代码引用 `@dimen/dp_<N>`，无需再手工换算。
4. 小数位：推荐 `--decimals 1`，比整数四舍五入更精确，文件体积差别可忽略。

## 局限

- **字体**建议用 sp 而非此方案——涉及无障碍字号设置。
- **非线性**比例（极小屏需要相对更大文字）本方案无能为力，需要人工覆写关键 dimen。
- 生成的 XML 较多时会增大 APK 资源索引，一般影响可忽略；若范围上千个值可考虑精简。
